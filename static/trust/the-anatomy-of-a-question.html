The Anatomy of
a Question
a turn that stops to ask

The most dangerous answer an agent can give is a confident one to a question it did not understand. Two of your things share a name; a value was never recorded; a step cannot be undone. A trustworthy agent does not pick one and carry on. It stops, and asks you.

The principle

Asking is a guarantee of the framework, not a virtue of the model. A language model can be taught to ask, and Uderia teaches it — but a guarantee cannot rest on a model's judgement, least of all a weak model's. So Uderia finds the ambiguity itself, in code, raises the question itself, refuses every tool past it, and keeps the question as a record with its own credential. The model's own asking is welcome on top; it is never the floor.

Everything below was driven live on 2 November 2026: every face through a fire drill on the test server, the card and the editor in a real browser, and the weakest model in use as the stress test.

Act I

Stuck — Uderia finds the ambiguity before the model guesses

An agent is asked to open the Sales graph. The user owns two knowledge graphs named Sales. Before PROP-011 the resolver reported the second as if it did not exist, and the model answered for one of them. Now the resolver raises a choose question in code — before any model has a chance to pick.

The raisers are Uderia's own resolvers — every place a name becomes an id: a graph, a repository, an agent, a data product. A name that matches more than one of the user's things is a question, not the first match.

Who may raise

Four voices, one record

Uderia (an ambiguity found in code), the agent (the model's own act), a data source (an MCP server that elicits mid-turn), or a relay (an expert's question carried up by its coordinator). The card says which — platform, agent, data source, relayed — so you always know whose question it is.

The model may ask too

One tool, three carriers

Ideate and Optimize agents hold TDA_AskUser; the planner can answer with plan_type: input_required instead of a plan; a self-correction can begin ASK_USER:; Focus and Ideate without tools can write a marked block. Every carrier lands in the same validator and the same ledger — and the text that teaches each exists in the prompt only while the component is in use for that agent.

Act II

Asked and recorded — the question is a record, not a sentence

A question is a row: who it is for, which turn, who raised it and from which step, its kind, one to four items with their options, why it blocks, when it expires — and a digest of the canonical question that the answer's credential will carry. It reaches you verbatim: the card renders the record, never a paraphrase.

the card

Under the answer that stopped: the options as buttons, Send held until one is picked, Decline and Not now, and remember for this session · always for this agent.

the composer rule

While a question is pending, what you type in the composer is your answer to it — a provide question needs no card at all. A new message that is not an answer supersedes the question, and the record says so.

the strip

The status strip reads Waiting for you — a quiet reading in the posture colour, never an alarm. The Needs Input panel lists what is waiting and what was asked, for this agent or all of them; the Assurance Inbox lists it across agents.

Interrupted, not terminal

The turn's record reads input_required — a state beside complete and failed, not a flavour of either. It is interrupted: the session stays open on it, the question is served again on reload in its live state, and every poller in the runtime asks one rule, turn_states.is_settled, never its own list of strings. A REST client that declares it accepts the state sees it; one that does not sees complete with the question attached — nothing that polls today breaks.

Act III

Held — three guarantees, enforced where the model cannot reach

A question changes what the rest of the turn may do. The ledger that holds it is armed before any engine runs and read at the tool chokepoints, the plan loop and the gate seams — the same places Agent Authority holds — so the guarantees do not depend on the model agreeing with them.

Guarantee 1

No tool runs past a question

The MCP adapter, the component manager and the platform tool all ask the ledger first. A pending question makes every call a refusal that names the question — the same chokepoints where a denied tool is refused, so there is no door the model can take instead.

Guarantee 2

The question reaches you as written

The finish seam appends the question's text to the delivered answer and stamps the record. What the model wrote around it stays; what it cannot do is rephrase, soften or drop the question — the card is rendered from the record, not from the prose.

Guarantee 3

The gates abstain, honestly

There is no answer to grade, so grounding, honesty and the retrieval check abstain and say why. A turn that asked is neither a pass nor a failure on the Trust Circle — it is a turn waiting on a person, and the Reviewed station reads it as exactly that.

One question at a time

Bounded per turn

An agent asks at most n questions per turn (its owner's setting, 1–8, default 1). A second question on the same turn joins the first as another item or is refused — a turn never becomes an interrogation.

Act IV

Answered and bound — the answer is a credential, and it is used once

When the question was raised, the owner was issued a resume binding: a signed token over the record's digest, for this person, for this question. The answer carries it. Uderia verifies it, consumes it in one guarded write, and starts the next turn of the same session with the chosen value bound in code — the step that asked finds the answer on the ledger and continues; no model re-derives what you chose.

Remembered answers

Say it once, for the session or for the agent

Use this for the rest of the session keys the answer to the ambiguity (ambiguous:knowledge graph:sales); always for this agent writes it into the agent's standing answers, which its owner can read and edit. The next time the same ambiguity arises the resolver takes the remembered value — and records that it did, on the turn, as any default is recorded.

Why a credential

Nobody answers for you

The binding is issued only to the question's owner and only when the question is served to them. A REST client, an MCP caller or a relay must present it; an agent never holds one. A reloaded card is answerable because the session load re-issues it to the owner — and to no one else.

Act V

Continued — wherever the turn was running

A conversation is the easy case: you are there. Uderia agents also run as experts under a coordinator, on a schedule, as a node in a flow, behind an MCP tool, and through connectors to systems you must sign into. A question must survive each of these — and the answer must go back to the run it came from.

In the live run a coordinator forwarded a question to its Focus expert; the expert did not need Uderia to find it — it called TDA_AskUser itself: "Which region are you referring to? North America · Europe · Asia Pacific · Latin America · Africa". The question was relayed up as the coordinator's own, answered from its own options, and the expert was continued with the answer. Two relays, one chain, one record each.

Act VI

Governed — how an agent asks is its owner's authority

Asking has a posture, like every other authority an agent holds. It lives in the agent's Authority card, unsigned, and weakening it is a recorded downgrade — an agent that stops asking is an agent whose behaviour changed, and the Trust Circle says so.

One toggle, three effects

The component in use — or absent

Needs Input is a system component. Switch it off for an agent and nothing of the act remains: the prompt text that teaches the model to ask is not there (it is a variable, empty when the component is off), TDA_AskUser is not offered, and Uderia's own questions are recorded, never raised. The agent carries no token of a capability it does not have.

A person's acts stay a person's

Answering is human_only

In Uderia's own catalog of operations, answering or withdrawing a question is marked human_only — listed, described, and never callable by an agent, not even one with the Platform role that lets it drive everything else. An agent that could answer its own questions would have no questions.

Act VII

Measured — the question that was not asked

Asking is on the ring. The Reviewed station carries a needs_input point: a turn that stopped to ask reads as waiting on a person; a turn that used a standing answer reads as a pass with the answer named; a turn with nothing to ask reads not-applicable. And the measure that matters most is the one about the turns that did not ask.

The measure

guessed_past_ambiguity

After the turn, a scorer reads the raisers' record: an ambiguity was found, the posture was observe, no question was raised, and the step picked one. That is a guess presented as an answer — scored, visible on the Quality card, counted in the agent's trend. Uderia never pretends the guess did not happen.

Honest limits

The model's own asking is a hypothesis on weak models. Standalone on Nova 2 Lite, no engine used a carrier; under a coordinator one expert did. The guarantee is Uderia's raising, not the prompt. A second expert may ask the same question again after the first was answered — the remembered-answer option covers it; a continuation that carries one answer to the whole chain is not built. Uderia raises only what it can see — a namesake among the user's own things, a missing input a step declares, a source that elicits — not every ambiguity a sentence can hold. The numbers that would justify going further (how often people answer, how fast, whether a second question follows a first) need real use; they are collected, not yet read.

Why this matters

An agent that guesses well is still guessing. The question is the one output a model cannot fake: it is raised in code where the facts are ambiguous, recorded with its own credential, held at the same chokepoints that hold every other authority, answered only by a person, and measured when it was not asked. That is what makes "I need to ask you something" a guarantee rather than a mood.
