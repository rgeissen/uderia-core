Published limits — not footnotes

The trigger does recall; the judge does precision. A false positive costs one judge call that clears the answer — never a wrong verdict, never a withheld honest refusal (all five of this run's are exactly that: honest refusals that named the database they could not read). The number that matters is the false-negative count, and it is 2, not the 0 this page published in June.

The two misses, by case id. oos09 ("manufacturing, retail, and healthcare cores contain vendor data") names no identifier at all — plain words only the judge can read. oos03 lists real identifiers (manufacturing_core, retail_core) after "several schemas, including" — the trigger reads a name standing next to a container word, not a list after one. Both stay published as the honest gap. One run is a reading, not a constant: the weak model drifts on different questions each run (19% and 14% across the two October runs), so the misses move too.

Recall climbed 0% → 25% → 100% in June across three iterations — the first run disproved the naïve deterministic-block design (it blocked 10 honest "not in my scope" refusals and missed a prose-only drift), which forced the tiered trigger-plus-judge architecture the framework now ships. The benchmark redesigned the framework.

What the reruns found

October: the gate had gone blind, and nothing else noticed. The first rerun measured 0% recall, 7 false negatives. A September fix taught the trigger that a name the turn's own results contain is a value, not a source — and the agent now finds databases by searching the catalog, whose listing names every database. So each out-of-scope database it reported was excused. Catalog results no longer count as data, and a Markdown code span counts as a quote; recall is back to 60%, every case pinned in CI. The same run found that a REST call asking for an agent that could not be loaded was silently answered by the default agent — recorded, open. A benchmark you rerun is a benchmark that can catch a regression the tests missed.

June: 36 back-to-back sessions exposed a multi-thread SQLite deadlock that froze the whole server — eliminated with a process-wide serialization layer before the benchmark could even finish. A benchmark hard enough to break things is a benchmark worth publishing.

Published limits — not footnotes

The one false negative is deliberate. Case uns-id-01 fails because a single novel identifier never triggers alone — the ≥3-identifier floor is the false-positive discipline that keeps the 0% column at 0%. The miss is published by case id and pinned in CI rather than tuned away.

"Unsupported" never means "false." The trigger checks support in the retrieved corpus — after a targeted second-chance re-search — and says exactly that, on the card and in the answer itself.

What the first run found

A supported quote ending in a period inside the quotation marks read as unsupported — trailing-punctuation brittleness in the quote matcher. Fixed in the production primitive; the failing case stays in the dataset as the regression. The benchmark improved Uderia on day one.

Method

Two proof forms — and why the second is stronger

Live + judge-labelled (structured lane)

Real turns, real drift, real cost

Ground truth needs semantic judgement ("did this answer drift?"), so an LLM judge labels it — the same judge the framework ships. Honest, but reproducing it needs a running server, credentials, and ~$0.30.

Deterministic + offline (knowledge lane)

A pure function anyone can re-run

"Is this claim in these chunks?" is decidable in code, so the benchmark is the production primitive on a committed dataset. Zero tokens, zero infrastructure — the published numbers are pinned in CI, and any change that moves them fails the build.

The standard

Every enforcement claim in these stories traces to one of these two benchmarks or to a named CI suite — 24,284 assertions across 371 suites at the last full run (2026-10-31). If a number on this page moves, a test fails first.
